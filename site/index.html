Eight agents reason about a stock. Code computes every number, and nothing ships until a checker verifies it.

QuantEra is a multi-agent equity research system designed as a LangGraph state graph. An orchestrator sends one request to eight specialist agents in parallel; each reads point-in-time data through a single as-of gate, an independent checker recomputes every figure, and a chief analyst writes the thesis from verified claims only. The roots have not changed: code calculates, the model reasons and narrates inside checks, and anything that fails a check is replaced or dropped, never shipped. Built today is the deterministic core: three research lenses, the grounding guards and the fallback, mapped from source further down.

    Known gaps

    Found while reading the code at the audited commit. Each is also listed under the component it affects, and each maps to a step in the roadmap above.

    Orchestration is one sequential Python function.

    The README describes a LangGraph migration in development, but there is no dependency or import yet. The lenses sit behind synthesize(), so the orchestrator can be replaced without touching them.

    5 of 14 fundamentals metrics can never produce a value.

    EV/EBITDA and interest coverage need fields the contract does not have. The three growth metrics are hard-coded unavailable, which also leaves the valuation-versus-growth disagreement rule unable to fire. Multi-year statements are already fetched, so growth is the cheapest fix.

    Grounding checks values, not claims.

    A number in the brief passes if it appears anywhere in the model's input, even attached to the wrong metric. Planned: bind each generated number to the field it describes.

    Tests pass locally, but nothing runs them automatically.

    90 unit tests passed during this audit. The repository's only workflow deploys this page. A pytest job on pull requests is a few lines of configuration.

    Data is not point-in-time.

    Statements carry fiscal period-end dates, not filing dates. That is fine for current research and wrong for any backtest. Planned: EDGAR company facts, which record when each figure was filed.

    Run it

    The code this map describes is kept on the archive/v0-code branch. It needs Python 3.11 or newer. Unit tests use mock sources and need no keys. A real request needs a Finnhub key for news and a Groq key for the model; without them, news returns no data and the brief falls back to the template.

    # get the code
git clone -b archive/v0-code https://github.com/karan-patel11/quantera-ai
cd quantera-ai
python3 -m pip install -e ".[dev]"

# .env
NEWS_API_KEY=your_finnhub_key
GROQ_API_KEY=your_groq_key

# API and UI on http://127.0.0.1:8000
uvicorn quantera.server.app:app

# unit tests (live integration tests excluded)
python3 -m pytest
